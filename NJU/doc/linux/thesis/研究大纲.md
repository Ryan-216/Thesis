# 毕业论文研究大纲

**题目：** 比特币开源社区开发者活动的影响因素：捐赠信息披露与社区讨论情感

**专业：** 图书情报学 · 硕士学位论文

**预计篇幅：** 约 100 页

---

## 整体逻辑主线

```
比特币开源社区的特殊性
    ↓
外部信息输入（捐赠信息披露）→ 影响开发者活动  ←─ 研究一
内部信息积累（社区情感）     → 影响开发者活动  ←─ 研究二
                                      ↓
                          活动之间的相互影响（代码↔讨论）
```

> **核心论点：** 在比特币开源社区中，开发者活动不仅受到实际金钱激励的驱动，更受到**信息层面**的塑造——外部捐赠信息的披露方式与内部社区情感状态共同构成了开发者行为的信息环境，并经由不同的心理与认知机制影响开发者的代码贡献与讨论参与。

## 第一章 绪论（约 10 页）

### 1.1 研究背景

- 比特币作为最具影响力的去中心化开源项目
  - 全球最高加密货币市值；GitHub 上星标超 76,000
  - 无公司主体，完全依赖志愿开发者维系运转
  - 开发者贡献的可持续性是比特币生态的核心挑战
- 开源软件开发的普遍困境：如何激励志愿者持续贡献
- 捐赠作为新型激励机制的兴起（GitHub Sponsors 2019 年上线）
- **本研究的独特切入点**：
  - 区别于"捐赠金额影响"的既有研究，聚焦于**捐赠信息披露本身**的影响
  - 比特币社区存在真实且可观测的两阶段信息披露（Brink 基金会）
  - 开源社区内部情感信息尚未得到充分研究

### 1.2 研究场景：比特币社区与 Brink 基金会

- Brink 成立于2020年，两阶段披露机制的运作方式
- 非定向披露（X 平台公告捐款）vs. 定向披露（官网公布受助名单）
- 为何这一场景适合识别信息效应：样本剔除4名受资助者，实现信息与金钱的干净分离

### 1.3 研究问题

- **RQ1**：外部非盈利基金会两种捐赠信息披露（非定向披露与定向披露）如何分别影响开发者活动？二者之间是否存在交互效应？
- **RQ2**：比特币开源社区内部讨论情感如何影响开发者的代码活动与讨论活动？活动之间是否存在相互影响的路径？

### 1.4 研究方法概述

- 多源数据融合：GH Archive、X 平台、Brink 官网、Google Trends、Yahoo Finance
- 研究一：面板数据固定效应模型 + 工具变量（IV/2SLS）
- 研究二：向量自回归模型（VAR）+ 格兰杰因果检验 + 脉冲响应函数

### 1.5 研究意义

**理论意义：**
- 填补信息披露作为激励信号这一研究空白：既有研究多关注实际捐赠额度，本研究将"信息"本身从"金钱"中剥离
- 在开源社区情境下检验期望理论与期望失验理论的适用性
- 引入情感即信息理论与目标手段替代理论解释社区内部情感动力学
- 揭示开源社区中代码活动与讨论活动之间的动态互动机制

**实践意义：**
- 为 Brink 等开源基金会设计信息披露策略提供实证依据
- 为比特币及其他开源社区的治理与激励设计提供参考
- 对图书情报学"信息传播与用户行为"议题的实证补充

## 第二章 理论基础与文献综述（约 15 页）

### 2.1 开源软件开发与开发者激励

- 开源软件的特征与发展历程（含可持续性危机背景）
- 开发者参与动机的理论框架
  - 内在动机：兴趣、声誉、自我实现、利他
  - 外在动机：职业发展、货币激励、人力资本积累
  - 内外动机的互动：自我决定理论、"挤出效应"
- 货币激励对开源开发者贡献的影响研究综述
  - GitHub Sponsors 机制研究（Shimada 2022；Zhang 2022；Conti 2023）
  - 非盈利基金会资助的差异（Overney 2020；Wang 2022b）
  - GitHub Sponsors（点对点）与基金会模式（中介型）的结构差异
- **研究空白**：信息披露本身的激励效应尚未被独立考察

### 2.2 信息披露的理论与实证

- 自愿信息披露理论（Voluntary Disclosure Theory）
- 信号理论（Signaling Theory）：信息不对称与信号传递（Spence 1973；Connelly 2011）
- 奖励信息披露与受众行为：来自众筹与知识贡献平台的实证证据（Huang 2021；Toubia 2013）
- **Brink 捐赠信息披露的独特场景**：
  - 非定向披露（Untargeted）：X 平台公布收到的捐款——激活期望，但不指名受益人
  - 定向披露（Targeted）：官网公布受资助开发者名单——明确因果链，但触发比较效应
  - 两次披露在时间上分离，可分别识别其效果

### 2.3 期望理论与期望失验理论

- 期望理论（Expectancy Theory，Vroom 1964）
  - 三要素：效价（Valence）、工具性（Instrumentality）、期望值（Expectancy）
  - 非定向披露 → 提升效价与期望值；定向披露 → 提升工具性感知
  - 期望理论在在线贡献情境中的已有应用（Huang 2021 众筹证据）
- 期望失验理论（Expectancy Disconfirmation Theory，Oliver 1980）
  - 期望形成 → 结果感知 → 确认/失验 → 满意/失望
  - 定向披露公布后，非受助开发者经历期望失验 → 后续动机削弱
  - 失验效应的调节因素：初始期望水平、时间动态
- 理论整合：两种披露序贯作用，产生"整体正向、交互负向"的复合效应

### 2.4 情感与信息处理

- 情感即信息理论（Affect-as-Information Theory，Schwarz & Clore 1983）
  - 个体将当前情感状态作为判断和决策的信息来源
  - 负面情感传递"问题存在"的信号，驱动问题导向行为
  - 情感信号的滞后传导机制
- 目标手段替代理论（Goal-Means Substitution Theory，Kruglanski et al. 2002）
  - 当不同手段均能实现同一目标时，某一手段的充分使用会减少对其他手段的需求
  - 代码活动与讨论活动均指向"解决项目问题"这一目标
- 开源社区中的情感研究综述及方法论局限（词典工具 vs. 大模型；截面 vs. 动态）

### 2.5 开源社区中的活动类型与相互关系

- GitHub 活动类型：Commit（CCE）、Pull Request（PRE）、Review（PRRE）、Issue（IE）
- 代码活动、审查活动与讨论活动的功能区分与响应机制差异
- 合并谬误的方法论讨论：分类建模的必要性
- 活动之间相互影响的既有证据与理论预期

### 2.6 本章小结

- 理论框架与研究假设对应关系总图

**3.2.2 数据清洗与匹配流程**

1. **开发者 ID 统一化**：GH Archive 使用数字型 actor_id，将其与 GitHub 用户名双向映射，剔除机器人账号（bot 账号，通过账号名称正则过滤）
2. **时间对齐**：统一以 UTC 时区、ISO 周（Monday-based）为时间颗粒，所有数据源均聚合至相同周标识
3. **样本筛选**：
   - 保留2022年1月至2023年12月（共105周）在 bitcoin/bitcoin 主仓库有至少一次活动的开发者
   - 剔除4名在观测期内实际获得 Brink 全职资助的开发者

4. **披露事件标记**：将 X 平台公告日期和 Brink 官网公告日期精确映射至对应 ISO 周，生成非定向披露金额变量（对数）和定向披露虚拟变量
5. **情感聚合**：对每条 Issue 评论进行句子级情感评分后，取周内所有评论评分的均值作为当周社区情感极性指标

### 3.3 方法论总述

**3.3.1 两种方法的问题定位**

| 方法 | 适用问题类型 | 应用于 | 核心解决的挑战 |
|------|------------|--------|--------------|
| 面板固定效应 + 2SLS | 识别外生冲击对个体的因果效应 | 研究一 | 内生性：开发者活动反向影响捐赠规模（反向因果）；个体异质性 |
| 向量自回归（VAR） | 刻画多变量系统的动态互动机制 | 研究二 | 双向因果：情感、代码活动、讨论活动三者相互影响，无先验主从关系 |

**3.3.2 固定效应模型的识别逻辑**

固定效应模型通过引入开发者个体固定效应 $u_i$（吸收不随时间变化的个体特征，如技能水平、初始动机偏好）和时间固定效应 $\theta_t$（吸收所有开发者共同面临的宏观时间趋势，如比特币价格周期），使核心系数 $\beta_1$ 识别的是"在控制个体差异与时间趋势后，捐赠披露信息变动对开发者活动的净效应"。在此基础上，工具变量（Google Trends 搜索指数）通过外生的公众关注度变化来驱动捐款金额的识别，进一步解决披露金额本身的内生性问题。

**3.3.3 VAR 模型的识别逻辑**

VAR 模型将情感、代码活动和讨论活动三个变量均视为内生变量，通过联立方程组的形式捕捉变量间的动态反馈关系，无需对因果方向作出先验假定。格兰杰因果检验在统计层面识别"哪个变量能预测另一个变量"，脉冲响应函数（IRF）则可视化呈现系统对外部冲击的动态响应路径，共同描绘情感与开发活动之间的动态传导机制。

### 3.4 伦理考量

- **数据公开性与合规性**：本研究所使用的全部数据均来源于公开渠道——GH Archive 是 GitHub 对外开放的事件归档服务（CC BY 4.0 授权），X 平台推文为公开账号的公开发布内容，Brink 官网信息为非盈利组织主动公开披露的资助记录，Google Trends 和 Yahoo Finance 数据均为面向公众的聚合统计数据。上述数据的研究性使用符合相关平台服务条款及学术研究惯例
- **开发者隐私保护**：分析所使用的开发者标识符为 GitHub 平台的公开用户名及数字 ID，不涉及私人联系方式、地理位置或未公开的个人信息。在所有汇报的统计结果中，均以聚合形式呈现，不对具体个人作出单独点名式描述（附录中披露事件列表除外，仅列出 Brink 官方已公开发布的受资助者信息）
- **数据安全**：原始数据存储于本地加密硬盘及受访问控制的服务器上，不对外分发；分析代码将在论文完成后通过 GitHub 匿名化仓库开放，以支持结果可复现性

## 第四章 捐赠信息披露对开发者活动的影响（约 27 页）

### 4.1 研究场景：Bitcoin Brink 生态

- Brink 基金会介绍：最大的比特币专项资助机构，众筹模式
- **两次信息披露的完整流程**（图示）：
  1. Brink 收到捐款 → X 平台公告（非定向披露）
  2. 开发者申请资助 → 官网公布受资助名单（定向披露）
- 披露事件列表：2022.01–2023.12 期间共 19 次非定向披露、多批次定向披露
- 研究场景的优势：
  - 信息披露与实际资金到达时间分离（可识别信息效应）
  - 有明确的外生事件节点（可做准自然实验）
  - 样本中剔除实际受资助者（4人），排除金钱效应干扰

### 4.2 研究假设

基于期望理论与期望失验理论，建立三组假设：

**H1（非定向披露的正向主效应）**
- H1：非定向捐赠披露正向影响开发者总贡献
- H1a：正向影响代码贡献；H1b：正向影响审查贡献；H1c：正向影响讨论活动

> 机制：非定向披露同时提升效价（Valence，资金存在增加潜在奖励感知）与期望值（Expectancy，资金可得性提升"我也可能被资助"的主观概率），激励贡献行为。

**H2（定向披露的正向主效应）**
- H2：定向捐赠披露正向影响开发者总贡献
- H2a：正向影响代码贡献；H2b：正向影响审查贡献；H2c：正向影响讨论活动

> 机制：定向披露通过展示"努力→绩效→资助"的真实案例，提升工具性感知（Instrumentality），激励非受助开发者效仿。

**H3（定向披露对非定向披露效应的负向调节）**
- H3：定向披露负向调节非定向披露对开发者贡献的正向效应
- H3a/b/c：对代码/审查/讨论贡献分别成立

> 机制：定向披露公布具体受益人后，未入选者经历负向期望失验，失望感削弱其对后续非定向披露所激活期望的响应强度。

### 4.3 数据与变量

> 本章分析基于第三章所述的整体数据集，具体使用2022年1月至2023年12月的周度面板数据（105周），并已剔除4名实际受到 Brink 全职资助的开发者，以确保样本中的所有1,613名开发者均未直接受益于捐款金额的转移，从而使分析聚焦于信息披露的纯信息效应。

**关键变量定义**

| 变量 | 类型 | 定义 |
|------|------|------|
| $\text{develop}_{it}$ | 因变量 | 开发者 $i$ 在第 $t$ 周的代码贡献，$\text{CCE}_{it} + \text{PRE}_{it}$ |
| $\text{review}_{it}$ | 因变量 | 开发者 $i$ 在第 $t$ 周的审查贡献，$\text{PRRE}_{it}$ |
| $\text{issue}_{it}$ | 因变量 | 开发者 $i$ 在第 $t$ 周的讨论活动，$\text{IE}_{it}$ |
| $\ln(\text{DonationAmount}_t)$ | 核心自变量 | 第 $t$ 周 Brink 在 X 平台公布的捐款金额（美元）的自然对数；无披露周取0 |
| $\text{TargetedDisclosure}_t$ | 核心自变量 | 虚拟变量：第 $t$ 周起 Brink 已公布受资助名单取1，此前取0（处理为阶跃变量） |
| $\text{DonationAmount}_t \times \text{TargetedDisclosure}_t$ | 调节变量 | 两者交互项，用于识别定向披露对非定向披露效应的调节 |
| $\text{GoogleSearchIndex}_t$ | 工具变量 | 第 $t$ 周"Brink Bitcoin"在 Google Trends 的搜索量指数（0–100标准化） |

**控制变量**：滞后一期因变量；Bitcoin 周对数收益率；Bitcoin 周交易量（对数）；开发者发起的 Fork 数（对数）；开发者 Watch 数（对数）；时间固定效应；个体固定效应

### 4.4 计量模型

**4.4.1 基准固定效应模型**

$$\ln(\text{Contribution}_{it}) = \beta_1 \ln(\text{DonationAmount}_t) + \beta_2 \text{TargetedDisclosure}_t + \beta_3 \ln(\text{DonationAmount}_t) \times \text{TargetedDisclosure}_t + \boldsymbol{\gamma}' \mathbf{X}_{it} + u_i + \theta_t + \varepsilon_{it}$$

模型中各成分的识别逻辑：
- $u_i$：开发者个体固定效应，控制技能水平、初始参与动机等不随时间变化的个体异质性
- $\theta_t$：时间固定效应，控制比特币价格周期、宏观技术趋势等所有开发者共同面临的时间趋势
- $\beta_1$：在控制个体差异与时间趋势后，捐款披露金额对开发者活动的**净信息效应**
- $\beta_3$：在定向披露发生后，捐款金额效应的边际变化量（预期为负）

**4.4.2 工具变量方法（2SLS）**

*内生性来源*：$\ln(\text{DonationAmount}_t)$ 可能存在反向因果——社区活跃度提升可能吸引更多捐款，进而影响 Brink 的披露行为，导致 OLS 估计上偏。

*工具变量构建*：使用 Google Trends 中关键词"Brink Bitcoin"在美国地区的周度搜索量指数（0–100标准化），通过 pytrends Python 接口采集，以2022年1月至2023年12月为时间范围，每次查询以日历周为粒度。

*工具变量有效性论证*：
- **相关性（Relevance）**：公众对 Brink 的搜索关注度与 Brink 收到的捐款金额正相关——Brink 的社会曝光度越高，吸引捐款的能力越强；一阶段 F 统计量应显著大于 10（将在实证结果中汇报）
- **排他性（Exclusivity）**：Google Trends 搜索量指数反映的是社会公众对 Brink 机构的一般性信息搜寻行为，不直接决定任何特定比特币开发者的个体贡献决策；搜索量的变动经由捐款金额这一中间变量才能影响开发者行为，不存在独立的直接影响路径

*两阶段估计*：

第一阶段：$\ln(\widehat{\text{DonationAmount}}_t) = \alpha_0 + \alpha_1 \text{GoogleSearchIndex}_t + \boldsymbol{\alpha}' \mathbf{X}_{it} + \eta_{it}$

第二阶段：使用第一阶段拟合值 $\ln(\widehat{\text{DonationAmount}}_t)$ 替换原变量，重新估计主方程

## 第五章 社区讨论情感对开发者活动的影响（约 22 页）

### 5.1 研究背景与问题

- 开源社区 Issue 讨论中蕴含丰富的情感信息：抱怨、兴奋、疑问、冲突
- 情感状态如何影响开发者的行为决策？
- 代码活动（解决问题）与讨论活动（协商问题）之间是否存在替代或互补关系？
- 时间序列视角：情感的动态传导过程

### 5.2 理论假设

**情感对开发者活动的影响路径**

基于**情感即信息理论**：
- Issue 中负面情感（情感极性下降）是项目面临冲突或技术难题的信号
- 开发者将此信号解读为"需要行动"，激励代码贡献与讨论参与
- → **H4：滞后一期负面情感正向影响代码活动**（情感极性↓ → 代码活动↑）
- → **H5：滞后一期负面情感正向影响讨论活动**

**代码活动对讨论活动的抑制路径**

基于**目标手段替代理论**：
- 代码活动与讨论活动共同服务于"解决项目问题"这一目标
- 当代码活动已充分展开，讨论活动作为替代手段的需求降低
- 人的精力有限，代码贡献的增加挤占讨论参与的资源
- → **H6：滞后两期代码活动负向影响讨论活动**

**完整影响路径**：
```
情感极性↓（t-1）→ 代码活动↑（t）→ 讨论活动↓（t+1）
情感极性↓（t-1）→ 讨论活动↑（t）
```

### 5.3 数据与变量

> 本章分析基于第三章所述的整体数据集，在社区层面（而非个体层面）进行聚合，使用2022年1月至2023年12月共105个周度观测，每周的情感极性、代码活动总量和讨论活动总量均为全体 bitcoin/bitcoin 仓库贡献者的聚合指标。

**5.3.1 情感分析方法**

- **数据范围**：bitcoin/bitcoin 仓库2022—2023年 Issue 区全部评论（约N条，待补充）
- **文本预处理**：
  1. 去除代码块（\`\`\`…\`\`\` 包裹的内容）和 URL
  2. 去除非英文字符（比特币社区以英文交流为主）
  3. 对超过512 token的长评论截断（BERT 类模型限制）
- **工具选择**：
  - 主分析：VADER（Valence Aware Dictionary and sEntiment Reasoner）——专为社交媒体短文本设计，对技术讨论中的特殊标点和强化词处理较好，已在开源社区研究中广泛应用，可直接离线运行
  - 稳健性检验：替换为基于预训练 RoBERTa 的情感分类器（如 cardiffnlp/twitter-roberta-base-sentiment），以验证结论对工具选择的不敏感性
- **验证方法**：随机抽取200条评论进行人工标注，计算工具输出与人工判断的一致率（Cohen's Kappa），若 $\kappa > 0.6$ 视为可接受
- **周级聚合**：取当周所有评论 VADER compound score 的算术均值，作为当周社区情感极性指标 $\text{Sentiment}_t \in [-1, 1]$

**5.3.2 关键变量**

| 变量 | 类型 | 定义 |
|------|------|------|
| $\text{Sentiment}_t$ | 内生变量 | 第 $t$ 周 Issue 评论情感极性均值，$[-1, 1]$，负值代表负面情感主导 |
| $\text{CodeActivity}_t$ | 内生变量 | 第 $t$ 周 CCE + PRE 事件总量（对数） |
| $\text{DiscussActivity}_t$ | 内生变量 | 第 $t$ 周 IE 事件总量（对数） |

### 5.4 研究方法：向量自回归模型（VAR）

**5.4.1 选择 VAR 的理由**

三个变量之间存在理论预期的双向影响关系，且无明确先验主从结构。单方程回归模型只能处理单向因果，无法识别动态反馈；VAR 模型将所有变量均视为内生变量，适合分析多变量时间序列系统中的动态因果关系，能够同时捕捉"情感→活动"和"活动→活动"两条路径，与研究问题的结构高度契合。

**5.4.2 分析步骤**

1. **平稳性检验**：对三个时间序列分别进行 ADF（Augmented Dickey-Fuller）单位根检验；若存在单位根则进行一阶差分处理，以确保 VAR 估计的有效性
2. **最优滞后阶数选择**：同时参照 AIC（Akaike Information Criterion）和 BIC（Bayesian Information Criterion）确定最优滞后期数 $p$；若两个准则结论不一致，优先选择较小的 $p$ 以避免过拟合（通常 $p = 1$ 或 $p = 2$）
3. **VAR($p$) 模型估计**：
   $$\mathbf{y}_t = \mathbf{c} + \sum_{k=1}^{p} \mathbf{A}_k \mathbf{y}_{t-k} + \boldsymbol{\varepsilon}_t$$
   其中 $\mathbf{y}_t = [\text{Sentiment}_t, \text{CodeActivity}_t, \text{DiscussActivity}_t]'$，$\mathbf{A}_k$ 为 $3 \times 3$ 系数矩阵，$\boldsymbol{\varepsilon}_t \sim N(\mathbf{0}, \boldsymbol{\Sigma})$ 为白噪声残差向量
4. **格兰杰因果检验（Granger Causality Test）**：对每对变量进行 Wald 检验，判断变量 $X$ 的滞后项是否对 $Y$ 的预测具有统计意义上的增量解释力；报告 $\chi^2$ 统计量与对应 $p$ 值
5. **脉冲响应函数（Impulse Response Function, IRF）**：基于正交化 Cholesky 分解，可视化系统对各变量单位标准差冲击的动态响应路径，展示效应在时间上的传播与衰减
6. **方差分解（Forecast Error Variance Decomposition, FEVD）**：量化各变量对其他变量 $h$ 步预测误差方差的贡献比例，衡量情感变量对代码活动和讨论活动波动的解释程度

**5.4.3 变量排序说明（Cholesky 识别）**

VAR 的正交化依赖变量排序假设，本研究设定排序为：情感 → 代码活动 → 讨论活动，即假设情感在同期内率先变化，代码活动次之，讨论活动最后响应。该排序与情感即信息理论关于"情感信号先于行为调整"的理论预期一致；稳健性分析中将检验不同排序的影响。

## 第六章 综合讨论（约 10 页）

### 6.1 两项研究的共同发现与内在联系

- 外部信息（捐赠披露）与内部信息（社区情感）共同构成开发者的信息环境
- 两者均通过信息的认知加工（而非直接物质激励）影响行为
- 开发者在信息环境变化时展现出理性但有限的反应模式

### 6.2 理论贡献

**对激励理论的贡献**：
- 将"信息披露"作为独立的激励机制从"实际激励"中剥离，丰富了激励理论的层次
- 期望理论与期望失验理论的联合应用揭示了"先扬后抑"的复合效应

**对开源社区研究的贡献**：
- 首次在比特币社区情境下将两种捐赠披露方式分别识别并检验
- 揭示了社区情感在时间维度上的传导路径，补充了社区动态研究

**对图书情报学的贡献**：
- 从信息行为视角重新审视开源开发者的活动模式
- 多源异构数据的融合方法为该领域的实证研究提供方法论参考
- 准自然实验的因果识别框架为该领域从相关向因果推断的范式转型提供示范

### 6.3 实践启示

**对开源基金会（如 Brink）**：
- 非定向披露应保持频率，维持社区成员的整体期望水平
- 定向披露的时机与方式需谨慎设计，以减轻非受助者的失望效应
- 可探索分层披露策略：先强调"机会面向所有人"再公布具体名单

**对 Bitcoin 及其他开源社区**：
- 建立情感监测机制，将社区情感极性作为项目健康度的先行指标
- 负面情感高峰期是潜在的代码产出高峰期，可作为项目管理的参考信号

### 6.4 研究局限

- 研究一：Brink 定向披露次数有限（样本内事件稀少），参数估计精度受限
- 研究一：工具变量（Google 搜索指数）的排他性假设无法完全验证
- 研究二：情感分析工具在技术性文本（代码相关讨论）上的准确性有待提升
- 数据时间范围：2022–2023 年，是否适用于其他时期和其他开源项目需进一步检验
- 未能区分情感的来源（核心开发者 vs. 外围参与者的发言权重不同）

## 第七章 结论（约 5 页）

### 7.1 主要研究结论

**研究一结论**：
1. 非定向捐赠披露（Untargeted Disclosure）正向影响开发者的代码贡献与审查贡献
2. 定向捐赠披露（Targeted Disclosure）正向影响开发者的审查贡献
3. 定向披露对非定向披露效应产生负向调节，印证了期望失验机制的存在
4. 上述效应独立于实际捐款金额的直接激励效应（已通过样本剔除和工具变量加以控制）

**研究二结论**：
1. 社区讨论中的负面情感（情感极性下降）滞后一期正向影响代码活动与讨论活动
2. 代码活动增加后滞后一期负向影响讨论活动
3. 存在"情感 → 代码/讨论 → 讨论"的影响路径

### 7.2 研究展望

- 拓展至其他加密货币开源社区（Ethereum、Monero 等）的跨社区比较
- 结合开发者调查数据，从主观认知层面直接验证心理机制
- 探究不同类型情感（愤怒 vs. 沮丧 vs. 焦虑）的差异化影响
- 研究捐赠信息披露与社区情感的**联合效应**（两个研究问题的整合框架）
